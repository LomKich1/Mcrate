## Что делаем
Десктопный плеер для Windows 11 на Rust. Играет музыку из Yandex Music, VK Music, SoundCloud и Spotify.
- Только клиент, своих серверов нет.
- Вход в сервисы по пользовательскому токену. Секреты и токены в код и в репозиторий не попадают никогда. Хранение: Windows Credential Manager (крейт keyring). В .gitignore уже есть .env, *.token, *.key, config.local.*.
- "Волна" как в Yandex Music. Сначала эвристика (лайки, пропуски, прослушивания, похожие треки из API сервисов), нейросеть только если появятся данные. Для Яндекса можно использовать его собственную волну через API.
- Интерфейс: чистый Rust-UI (не Tauri и не веб), аккуратный liquid glass, ориентир: проводник Windows 11. Блюр окна через системный механизм DWM (Mica/Acrylic, Windows 11 сборка 22621+), без костылей. Блюр внутри приложения рисуем сами шейдерами (wgpu). Экран настроек графики с детальной настройкой и полным отключением блюра. Конкретный UI-фреймворк ещё не выбран, выбираем под шейдерный блюр.
- Позже: встроенный AmneziaWG (или аналог с теми же конфигами), автогенерация конфигов с проверкой на основе конфигов Cloudflare WARP, плюс загрузка своего конфига. Желательно userspace-туннель только для трафика плеера, без драйвера TUN и прав администратора.
- Свои треки: пользователь может добавить локальные аудиофайлы (mp3, flac, ogg, wav, m4a и др. форматы, которые поддерживает symphonia/rodio; точный список проверим на практике). Добавление через drag&drop в окно (UI) и через выбор файлов/папки. Это провайдер LocalProvider наравне с остальными сервисами: без токенов, без сети.

## Подводные камни (учитывай)
- Официальных API у Yandex Music и VK Music нет, у SoundCloud новые приложения почти не регистрируют. Всё через неофициальные токены, может сломаться, нарушает правила сервисов.
- Spotify: официальный API только управляет воспроизведением. Звук локально возможен лишь с Premium и неофициальным librespot. Самый рискованный сервис, делаем последним.
- VK отдаёт зашифрованный HLS, Yandex подписывает ссылки на файлы. Проверяй актуальное состояние перед реализацией.
- boringtun (Rust-WireGuard) не умеет обфускацию Amnezia, скорее всего нужен amneziawg-go отдельным процессом. Лицензию проверить.
- Cloudflare WARP, насколько известно, поддерживает только часть обфускации (Jc/Jmin/Jmax). Проверять на практике.
- Cargo не замечает файлы, распакованные из архива (у них старое время изменения): после распаковки выполнить `cargo clean -p <крейт>`. Признак: тесты не добавились, а сборка кончилась за доли секунды без `Compiling`.
- Общий таймаут на HTTP-запрос (`.timeout`) ломает скачивание на медленном интернете: у LomKich около 87 КБ/с, скрипт в 1 МБ не влезает в 25 с. Ставим `connect_timeout` и `read_timeout` (время молчания), общего таймаута нет.

## Правила работы вдвоём (ОБЯЗАТЕЛЬНО)

Работаем вдвоём в одной ветке main. Чтобы не затирать код друг друга, git-цикл соблюдаем всегда. Один из нас новичок в git, поэтому ты (Claude) обязан:
- в начале каждой рабочей сессии напомнить сделать `git pull`;
- после КАЖДОГО законченного изменения (новая функция, исправление, правка конфигов) сам напомнить про коммит и push и дать точные команды ниже;
- объяснять каждую команду простыми словами, не предполагать, что человек её знает;
- не давать пользователю продолжать работу, пока он не подтвердит, что push прошёл.

### Начало работы
git pull
(скачивает свежий код от напарника; делаем ВСЕГДА перед тем, как что-то менять)

### После каждого законченного изменения
1. cargo build
   (проверка, что код собирается; сломанный код в main не отправляем)
2. git status
   (смотрим, какие файлы изменены; если видишь .env, токены или ключи, СТОП и ничего не добавляем)
3. git add .
   (подготовить изменения к сохранению)
4. git commit -m "коротко, что сделал"
   (сохранить версию локально)
5. git pull
   (ещё раз подтянуть чужие изменения, пока ты работал)
6. git push
   (отправить свою версию на GitHub)

### Если что-то пошло не так
- Конфликт при pull (git пишет CONFLICT): остановиться, ничего не удалять, показать Claude полный вывод и разбирать по шагам.
- Никогда не использовать `git push --force` и `git reset --hard` без согласования с напарником: они стирают чужую работу.
- Коммиты маленькие, по одной задаче, чтобы напарнику было легко читать.
- Общие интерфейсы (трейты в mcrate-core) меняем только после согласования друг с другом.
- Новые решения (фреймворк, крейты) записываем в этот файл.

## Принятые решения
- Звук: отдельный крейт mcrate-audio поверх rodio 0.23 (внутри symphonia + cpal). Свой конвейер на symphonia + cpal сделаем позже, когда понадобятся HLS и своя буферизация.
- Разделение: дорожка A (движок: mcrate-core, mcrate-audio, mcrate-providers) и дорожка B (интерфейс: mcrate-app, UI-фреймворк, drag&drop). Drag&drop делает B и передаёт пути в LocalProvider.
- Поиск идёт сразу по всем подключённым сервисам (параллельно, у каждого свой таймаут). Результаты показываются вместе с подписью источника (Track.provider); ошибки сервисов (нет авторизации, нет подписки, таймаут) показываются отдельно, не ломая остальной поиск. Трек между сервисами не сопоставляем: пользователь сам выбирает вариант. Агрегатор: SearchHub в mcrate-providers.
- Токены: только Windows Credential Manager через TokenStore, в тестах только выдуманные.
- Музыкальные файлы в папку репозитория не кладём (.gitignore аудио не игнорирует).
- UI-стек: eframe/egui 0.37 (wgpu) + egui_glass 0.2 (блюр и рефракция шейдерами), material-colors (Material 3), rfd (диалоги файлов), serde (настройки оформления). Mica/Acrylic через winit (только Windows). Настройки оформления не секретные, лежат в файле данных eframe.
- Библиотека своих файлов хранится в `%APPDATA%\Mcrate\library.txt` (пути, по одному в строке), запись через временный файл и переименование. Недоступные при загрузке пути возвращаются списком и стираются из файла при следующем сохранении.

- Разведка 14.11.2026 (проверено запросами с ПК LomKich, пробник `sc_probe`):
  - SoundCloud: официальный API требует платный Artist Pro, поэтому используем неофициальный `api-v2.soundcloud.com` с публичным `client_id`, который берётся из скриптов soundcloud.com (рабочий способ, при 401/403 `client_id` добывается заново). Может быть закрыт в любой момент. Из поиска берём только `policy=ALLOW`; `SNIP` это 30-секундные превью.
  - Потоки SoundCloud (выборка из 20 треков, 18 ALLOW и 2 SNIP): у полных треков (`ALLOW`) только `aac_160k` и `aac_96k` по HLS (куски fMP4, без шифрования, плейлист VOD с `EXT-X-MAP`) и `abr_sq` (мастер-плейлист). MP3 (`mp3_1_0` по HLS и по прямой ссылке) есть только у превью (`SNIP`). Берём `aac_160k`, запасной `aac_96k`, MP3 оставлен последним запасным вариантом и на полных треках, судя по выборке, не встречается (флаг `--mp3` в `sc_play` бесполезен).
  - `client_id` добывается с сайта (скрипты по ~1 МБ, на медленном интернете около 30 с), поэтому хранится в `%APPDATA%\Mcrate\soundcloud_client_id.txt` (он публичный) и берётся оттуда; при ответе 401/403 файл стирается и `client_id` добывается заново.
  - Декодер (rodio 0.23, symphonia 0.5.5) играет склеенный fMP4 (init + куски) и перематывает его (проверено на синтетическом файле такого же формата); общую длину для такого файла не знает (None), берём длину из данных поиска.
  - VK Music (из одного внешнего источника, не проверено нами): приватные методы `api.vk.ru`, вход по кукам `p` и `remixsid`, токен живёт около 15 минут, поток HLS с AES-128 на каждом третьем куске. Нужен отдельный аккаунт (риск бана).
  - YouTube и YouTube Music: PO-токены на каждое видео, принудительный SABR, подпись ссылок решается JS-кодом. Откладываем; возможный путь только внешний `yt-dlp` как необязательный плагин.
- Скачивание потоков: `StreamDownloader` качает трек целиком (DirectUrl или HLS) и отдаёт байты или файл, плеер играет файл. Шифрованный HLS, живые эфиры и `BYTERANGE` отклоняются с понятной ошибкой.

## Контракт звука: PlaybackEngine (mcrate-audio)
Единая точка входа в звук для UI. Движок живёт в своём потоке; UI шлёт команды, читает события и снимок состояния.
- Создание: `PlaybackEngine::new(providers: Vec<Arc<dyn MusicProvider>>)`. Звуковое устройство открывается внутри потока движка.
- Команды (не блокируют UI, берут &self): `play_queue(Vec<Track>, start)`, `add_to_queue(Track)`, `toggle_pause()`, `next()`, `prev()`, `seek(Duration)`, `set_volume(0.0..=1.0)`, `set_shuffle(bool)`, `cycle_repeat()`, `stop()`.
- События: UI каждый кадр вызывает `poll_events()`. Виды: TrackChanged(Option<Track>), PauseChanged(bool), ModeChanged{shuffle, repeat}, QueueChanged{len}, TrackFailed{track, reason}, QueueEnded, Error(String).
- Снимок: `state()` возвращает PlaybackState (current, position, duration, is_playing, volume, shuffle, repeat, queue_index, queue_len). Позиция для полосы перемотки берётся из снимка, не из событий.
- В очереди лежат Track. Ссылку на звук движок запрашивает у провайдера в момент проигрывания (ссылки сервисов протухают). Сейчас поддержан только StreamSource::LocalFile.
- Битый трек пропускается, причина приходит событием TrackFailed.
- `prev()`: если трек играет дольше 3 секунд, перезапускает его, иначе переходит к предыдущему.
